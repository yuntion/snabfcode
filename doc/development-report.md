## 1. 阶段结论

已经打通从模型 MLIR、HEIR 降低、Lattigo Go 代码生成到密文执行和明文对照的完整链路。固定参数的 `Linear → SiLU → Linear` 对照组在服务器上通过 **64 次加密推理、256 个输出检查**。项目也分别验证了子群塔路由的跨层密钥共享，以及 `DownConv` 对可保留槽位和冲突槽位的处理。

这些结果把对照组、测试工具和后端接口固定下来。**首个论文实验 E01 的核心是让四个 Pass 在同一份输入上共同决定实际执行计划**，用生成的程序和可回查的决策记录，说明哪项联动降低了成本或避免了精度失效。现有对照结果不计为联合优化结果。

## 3. 实测结果

对照图由两个 4×4 公开矩阵和中间的 SiLU 构成。测试输入为 `[-1,1]^4` 的 16 个角点及 48 个固定随机种子样本。每次执行生成的密文程序，解密后逐槽与独立的 `float64` 明文参考比较，并核对运行时实际使用的 `Q/P` 与冻结文件一致。

| 指标 | 记录值 |
|---|---:|
| 加密推理通过率 | 64 / 64 |
| 检查输出 / 超阈值输出 | 256 / 0 |
| 最大绝对误差 | `9.15e-5` |
| 均方误差（MSE） | `2.40e-10` |
| 绝对误差门槛 | `2^-12 ≈ 2.44e-4` |
| 环维数 `N` | `16384` |
| 活跃 RNS 层号（从 0 开始） | `7 → 0` |
| 实测 `log2(scale)` | `26 → 51.96` |
| 平均密文求值耗时 | `156.27 ms`，不含密钥生成、预处理、加密及解密 |

两项结果直接影响后续设计：

1. **具体参数必须回查。** 初次编译的末级 scale 接近 `2^80`，而该活跃模数仅约 50 bit，数值对照失败。为输出保留足够模数空间后，原电路在同一误差门槛下通过。E01 将对实际落地的链和尺度做回查，而不是只读求解器的抽象 bit 数。
2. **降环必须保持逻辑槽语义。** 从 `N=16384` 降到 `8192` 的独立密文测试中，8 个稀疏复数槽的转换前后最大差为 `4.24e-10`，活跃 level 与 scale 不变。全填充反例用原生投影把同组的 `0.75` 和 `-0.25` 合并为 `0.25`，项目的保值转换接口拒绝了这一输入。

上述精度为实测误差，耗时只记录本次对照组；它们不替代联合优化的性能对比、具体安全估计或输出误差证书。

## 4. 构建状态与近期交付

服务器为 Ubuntu `22.04.3 LTS`，处理器为 AMD EPYC 9754。对照链路使用官方 `heir-py 2026.11.1` 的编译器、Go `1.26.0` 和 Lattigo `v6.2.0`；项目 C++ 链接 HiGHS `v1.16.0`。HEIR 源码锁定在 `368d0b17ee5dfc26e5da2fb417c63e368cff8ab7`，配套 Bazel `8.4.0`。上游源码测试仍停在 `bazel_skylib` 等依赖下载阶段，没有进入编译。发布版工具用于保留可复现的对照组；自定义方言和 Pass 的验收以可注册这些组件的源码构建为准。

| 顺序 | 交付 | 验收依据 |
|---|---|---|
| 1 | 注册 `snabf` ODS，连接前端、SSA 预算和子群路由 | 同一份 MLIR 能生成启用/关闭路由后的不同程序，保持解密输出一致，并记录旋转、密钥、level 和 scale |
| 2 | 将 SiLU 的复合多项式候选交给参数规划器 | 保留真实求值 DAG 的 Pareto 候选；有候选区间和误差证据；选中的参数能生成具体素数，至少一个被接受的非零截断在密文算子中执行 |
| 3 | 将布局合法的降环纳入反馈规划，跑完整 E01 | 对照和联合方案使用同一输入及精度/安全标准；联合方案真实执行转换并在小环上跑后缀；记录接受和拒绝原因，对所有公开密钥实例做一致的安全筛查 |

E01 的正式输入拟沿用 `Linear → SiLU → Linear`，把线性层扩到 64×64 或更宽，保留足够的降环后工作，并加入跨转换位置的残差边。对比固定 HEIR/Lattigo、逐区域贪心和联合规划，同时用固定环、关闭截断的对照定位收益来源。第一条能解释联动收益或失效差异的完整结果即可用于起草实验节；不等全部 workload 跑完再写。
